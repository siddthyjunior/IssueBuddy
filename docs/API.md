# IssueBuddy Phase 2 — API Reference

Base URL: `http://localhost:8080`

All endpoints except `GET /`, `GET /health`, and `POST /api/auth/login` require:

```http
Authorization: Bearer <access-token>
Content-Type: application/json
```

## Authentication

### `POST /api/auth/login`

```json
{ "email": "admin@issuebuddy.local", "password": "ChangeMe123!" }
```

Returns `{ "token": "...", "user": { "id": "...", "name": "...", "email": "...", "role": "ADMIN" } }`.

### `GET /api/auth/me`
Returns the authenticated user. Access tokens expire after 12 hours.

### `POST /api/auth/logout`
The API confirms the request; the browser removes the stateless bearer token locally.

## Users

- `GET /api/users` — list all users (ADMIN only).
- `GET /api/users?projectId=<uuid>` — list members of a project (project member or ADMIN).
- `POST /api/users` — create a user (ADMIN only). Body: `{ "name", "email", "password", "role" }`.
- `PATCH /api/users/:id/active` — activate/deactivate a user (ADMIN only). Body: `{ "isActive": false }`.

## Projects, members and labels

- `GET /api/projects` — projects visible to the user (ADMIN sees all).
- `POST /api/projects` — create a project (global ADMIN or MANAGER). Body: `{ "name", "key", "description" }`. Key must be 2–12 uppercase alphanumeric characters and start with a letter.
- `GET /api/projects/:projectId` — project detail.
- `GET /api/projects/:projectId/members` — project members.
- `POST /api/projects/:projectId/members` — add/update a member (project MANAGER). Body: `{ "userId": "uuid", "role": "DEVELOPER" }`.
- `DELETE /api/projects/:projectId/members/:userId` — remove a member (project MANAGER).
- `GET /api/projects/:projectId/labels` — list project labels.
- `POST /api/projects/:projectId/labels` — add a label (project MANAGER). Body: `{ "name": "bug", "color": "#ef657b" }`.

Project roles are `MANAGER`, `DEVELOPER`, `VIEWER`. Global ADMIN bypasses project membership checks.

## Issues

### `GET /api/issues`
Required query: `projectId=<uuid>`. Optional query: `status=OPEN|IN_PROGRESS|REVIEW|CLOSED`, `priority=LOW|MEDIUM|HIGH|URGENT`, `q=<search>`, `page=1`, `pageSize=50` (maximum 100). Returns `{ page, pageSize, total, data }`.

### `POST /api/issues?projectId=<uuid>`

```json
{
  "title": "Login button not working",
  "description": "Clicking the login button does nothing on Chrome.",
  "status": "OPEN",
  "priority": "HIGH",
  "assigneeId": null,
  "labelIds": []
}
```

Issue keys are generated by the project sequence (for example `DEMO-5`). Creating issues requires project MANAGER or DEVELOPER access.

### Other issue routes

- `GET /api/issues/:issueId` — issue details, assignee, reporter, labels and attachment metadata.
- `PATCH /api/issues/:issueId` — update one or more of `title`, `description`, `status`, `priority`, `assigneeId`, `labelIds`.
- `DELETE /api/issues/:issueId` — delete an issue (project MANAGER or ADMIN).
- `POST /api/issues/bulk` — update up to 100 issue IDs in a project. Body: `{ "projectId", "issueIds": [], "status"?, "priority"?, "assigneeId"? }`.

## Comments and activity

- `GET /api/issues/:issueId/comments` — list comments.
- `POST /api/issues/:issueId/comments` — body `{ "body": "A comment" }` (1–5000 characters).
- `GET /api/issues/:issueId/activity` — latest 100 activity entries.

## Attachments

- `POST /api/attachments/issues/:issueId/attachments` — multipart form-data key `file`. PNG, JPEG, WEBP, PDF and TXT are accepted, maximum 10 MB. Project MANAGER or DEVELOPER required.
- `GET /api/attachments/:attachmentId/download` — authenticated download; requires access to the parent project.

## Notifications

- `GET /api/notifications` — latest notifications and unread count.
- `PATCH /api/notifications/:id/read` — mark one notification read.
- `POST /api/notifications/read-all` — mark all current user's notifications read.

## Analytics

- `GET /api/analytics/projects/:projectId/analytics` — issue totals, status counts, priority counts, assigned-to-me count, and recent issues.

## Status and priority values

Statuses: `OPEN`, `IN_PROGRESS`, `REVIEW`, `CLOSED`.

Priorities: `LOW`, `MEDIUM`, `HIGH`, `URGENT`.

## Error responses

- `400` — invalid input / validation failure.
- `401` — missing or invalid access token.
- `403` — insufficient role or project access.
- `404` — resource or route not found.
- `409` — unique value conflict (for example duplicate email/project key).
- `500` — unexpected server error.
